The Problem: Code Does Not Run

Large-scale study on research code quality
Nature Scientific Data, 2022

Analysis of 2,000+ replication datasets with 9,000+ R files (2010–2020):

  • 74% failed on first run
  • 56% failed even after automated code cleaning

Most common causes: missing packages, hardcoded paths, wrong execution order

The same failure modes apply to Python. This course teaches you to avoid all of them.

You run your analysis, submit the paper.
One year later, you need to extend it.

Problems you will face:

  • Python package APIs changed → code breaks
  • You forgot the sequence of steps
  • Your collaborator can’t run it at all

→ Every problem has a fix. We implement them today.

Five Fixes for Reproducibility

Problem Fix
Hardcoded absolute paths (C:/user/data/file.csv) Use relative paths (data/file.csv)
Unclear which packages & versions pip freeze > requirements.txt
Scripts run in wrong order Taskfile with numbered dependencies
Code untested on clean machine Test in fresh venv before sharing
Proprietary software Use free & open-source tools

Source: Trisovic et al. (2022), Nature Scientific Data

Four pillars of a reproducible project:
Version control (Git) · Consistent structure · Documentation (README) · Automation (Taskfile)

Step 1 — Virtual Environment: venv

venv vs conda

venv conda
Built-in ✅ ❌ (install separately)
Lightweight ✅ ❌
Own Python per env ❌ ✅
Non-Python deps ❌ ✅ (R, C libs)
For this course ✅ sufficient Optional

Use .venv as the folder name — VS Code detects it automatically, and GitHub’s Python .gitignore template excludes it automatically.

# 1. Create virtual environment
python -m venv .venv

# 2. Activate (Mac / Linux)
source .venv/bin/activate

# 2. Activate (Windows)
.venv\Scripts\activate

# 3. Install packages
pip install pandas statsmodels \
  linearmodels wrds matplotlib \
  seaborn jupyterlab ruff

# 4. Freeze exact versions
pip freeze > requirements.txt

# 5. Deactivate when done
deactivate

Step 2 — Package Managers

pip (default, always available)

pip install pandas
pip install -r requirements.txt  # reproduce
pip freeze > requirements.txt    # export

uv (modern — written in Rust, very fast)

pip install uv
uv pip install pandas
uv pip freeze > requirements.txt

Why pinned versions matter:
statsmodels 0.13 → 0.14 changed default standard errors. Without requirements.txt, your results may not reproduce — even on your own machine next year.

# requirements.txt (example)
pandas==2.2.1
numpy==1.26.4
statsmodels==0.14.1
linearmodels==5.4
matplotlib==3.8.3
seaborn==0.13.2
wrds==3.2.0
python-dotenv==1.0.1
jupyterlab==4.1.5
ruff==0.4.2

Anyone can now reproduce your environment exactly:

python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

Step 3 — Code Quality: ruff

Linters detect problems before you run code:

  • flake8 — style + error checking
  • pylint — deeper analysis
  • mypy — static type checking
  • ruff — replaces all of the above + formatting

Formatters auto-format your code:

  • Black — opinionated formatter
  • isort — sorts import statements
  • ruff — does both

💡 Install only ruff. One tool, written in Rust, replaces flake8 + Black + isort. Orders of magnitude faster.

# Check for issues
ruff check code/

# Auto-fix issues
ruff check --fix code/

# Format code
ruff format code/

pyproject.toml (minimal config):

[project]
name = "sme-internationalization"
requires-python = ">=3.10"

[tool.ruff]
line-length = 88
exclude = [".venv"]

[tool.ruff.lint]
select = ["E4", "E7", "E9", "F"]

[tool.ruff.format]
quote-style = "double"
indent-style = "space"

Step 5 — Automation with Taskfile

pip install go-task-bin

Taskfile.yml — enforces the correct execution order:

version: '3'

tasks:
  pull:
    cmds:
      - python code/01_pull_data.py

  clean:
    deps: [pull]
    cmds:
      - python code/02_clean.py

  descriptives:
    deps: [clean]
    cmds:
      - python code/03_descriptives.py

  regression:
    deps: [descriptives]
    cmds:
      - python code/04_regression.py

  all:
    deps: [regression]
task all         # runs the full pipeline
task regression  # runs only regression (+ its deps)

Anyone cloning your repo runs task all — one command, correct order, reproducible.

Step 7 — Pandas or Polars?

For this project: pandas

  • Time series data (firm-years) → pandas aligns on index automatically
  • statsmodels and linearmodels expect pandas DataFrames
  • Larger ecosystem, more Stack Overflow answers

Pandas index trap (know this!):

df = pd.DataFrame({'Customer': ['A','B','C','D','E'],
                   'Sales': [100,500,200,600,300]})
high = df[df['Sales'] > 400].copy()

# ✅ Works: scores is a plain list
high['Score'] = [10, 20]

# ❌ Silent bug: pandas aligns on original index
high['Score'] = pd.Series([10, 20])
# Fix:
high.reset_index(drop=True, inplace=True)
high['Score'] = pd.Series([10, 20])

When to use Polars instead:

  • Large datasets (millions of rows) → much faster
  • General data transformation (no time series alignment needed)
  • Written in Rust; lazy evaluation

Save your cleaned data as Parquet:

import pandas as pd

df.to_parquet("data/processed/panel_clean.parquet")
df = pd.read_parquet("data/processed/panel_clean.parquet")

Parquet vs CSV: Parquet is columnar, compressed, schema-aware, and 10–100× faster to read/write for large datasets. Use it for anything you’ll re-read often.

Step 8 — Reference Management with Zotero

Setup (once, ~10 minutes)

  1. Download Zotero + browser connector
  2. Install Better BibTeX plugin
  3. Point Zotero storage → references/ in your project
  4. Configure auto-export → references/library.bib

Daily workflow

  • Find paper → click browser connector
  • PDF saved to references/ automatically
  • library.bib updates without any manual step

Cite in research_note.md:

---
title: "SME Internationalization"
bibliography: references/library.bib
---
SMEs face liability of foreignness
[@Zaheer1995], which increases with
internationalization [@Lu2001].

Render with Quarto:

quarto render research_note.md
# → research_note.pdf
# → research_note.html

Docs: quarto.org/docs/guide
Gallery: quarto.org/docs/gallery

Jupyter vs Quarto — When to Use Which

JupyterLab Quarto .md
Format .ipynb (JSON blob) Plain text — clean Git diffs
Best for Exploration & prototyping Final reproducible output
BibTeX citations ❌ not built-in ✅ native
Renders to HTML PDF, HTML, Word, slides
Version control ❌ messy diffs ✅

Recommended workflow:
Explore in JupyterLab → finalize pipeline as numbered .py scripts → write research_note.md in Quarto → task all runs everything.

Other tools worth knowing: marimo (reactive Python notebooks), knitr (R equivalent of Quarto)

Step 9 — Research Question

A good RQ is…

  • Focused — one phenomenon
  • Grounded — linked to theory
  • Falsifiable — answerable with data
  • Relevant — fills a gap

Template: > “How does [X] affect [Y] among [population], and does [Z] moderate this?”

Theoretical anchors:

  • Uppsala model (Johanson & Vahlne 1977)
  • Liability of foreignness (Zaheer 1995)
  • SME internationalization & performance (Lu & Beamish 2001)
  • Absorptive capacity (Cohen & Levinthal 1990)

Our project’s RQ:

“Does degree of internationalization (DOI) exhibit an inverted U-shaped relationship with firm performance among European SMEs, and does R&D intensity moderate this relationship?”

Theory → prediction:

Early DOI: learning gains + market diversification → ↑ performance

High DOI: coordination costs + cultural distance + managerial complexity → ↓ performance

R&D-intensive firms: stronger absorptive capacity → threshold is higher

Step 10 — Hypothesis Derivation

Theory  →  Theoretical argument  →  Testable prediction  →  Falsifiable hypothesis

H1 — Non-linearity (inverted U-shape)

Buckley & Casson (1976): internalization benefits early.
Zaheer (1995): foreignness costs increase with DOI.
Lu & Beamish (2001): inverted U documented in SMEs.

H1: DOI positively affects performance at low levels; the effect turns negative at high levels.
Test: β(DOI) > 0 and β(DOI²) < 0

H2 — Moderation by R&D intensity

Cohen & Levinthal (1990): absorptive capacity enables firms to exploit external knowledge.
R&D → stronger capacity to learn from foreign markets → sustained performance at higher DOI.

H2: R&D intensity positively moderates the DOI–performance relationship.
Test: β(DOI × R&D) > 0
